# 日志触发词动画（彩蛋动画）设计文档

日期：2026-11-11
状态：已过独立审阅（无需向作者追问），待作者确认后开工

## 意图与缘由

灵感来自 QQ 音乐：歌词唱到「烟花」时，界面上会绽放一段烟花动画。
作者希望 `@wb04307201/pretty-log` 也有同款惊喜——输出日志时，内容命中特定词组
（如「烟花」），页面上就播一段对应的小动画。

这是一个彩蛋（easter egg）：目的纯粹是让人会心一笑。它绝不能反过来干扰开发者
正常使用页面，也不能拖累日志本身。

## 目标（Goals）

1. 日志内容（标题 + 正文，stringify 后的文本）命中触发词时，在页面上播放对应动画。
   触发时机 = 日志输出的那一刻。
2. 内置三个动画（手感已在浏览器 mockup 中逐一确认，三个全保留）：
   - **烟花**（爆发型）：火箭拖尾升空，炸开成一圈彩色火星，带重力缓缓落下。
     触发词：`烟花`。
   - **撒花**（轻柔型）：彩色纸屑打转、摇摆、缓缓飘落。
     触发词：`撒花`、`庆祝`、`好耶`。
   - **下雪**（氛围型）：大小不一的雪花慢悠悠斜飘，安静落一会儿。
     触发词：`下雪`、`雪花`。
3. 「触发词 → 动画」映射表可配置：使用者可以加自己的词、改映射、整体关闭。
4. **防轰炸**：同一时刻全局最多一个动画在播；播完约 2 秒冷却；播放中或冷却期内
   再命中直接跳过。连续打一百条含「烟花」的日志，也只看到一次绽放。
5. **不干扰用户操作**：动画是 `position: fixed` 的全屏透明层，`pointer-events: none`，
   播放期间页面照常可点、可选、可输入。

## 非目标（Non-goals）

- 不做声音、不做 WebGL、不引入任何新依赖。
- 不支持使用者自定义全新的动画类型——映射表只能映射到内置三种动画；
  「加第四种动画」是将来的事，本次设计只保证加起来便宜（参数级扩展）。
- 不改日志输出格式；动画不进 history、不参与 level 过滤文案。

## 反目标（Anti-goals）——出现任何一条即视为失败

- 动画喧宾夺主：挡住点击、打断输入、抢焦点、挥之不去。
- **触发词误伤**：把业务日志高频词（如「成功」「完成」「加载」）当触发词，
  导致每条普通日志都播动画。默认词表只收业务日志里几乎不会出现的感叹性词
  ——命中了就该是用户故意打出来的。
- 拖慢日志：未命中触发词时开销可忽略（简单子串匹配，且仅在效果开启时执行）。
- 生产环境播动画：与日志一致，`NODE_ENV=production` 整体 no-op。
- 包体膨胀：粒子引擎自写、轻量，不引第三方动画库。

## 约束（Constraints）

- 保持零依赖；`yarn build`（Parcel）产物兼容现有 main/module/types 出口。
- **测试跑在 Node、无 DOM**：触发匹配、冷却、配置等逻辑必须可在无 DOM 环境下单测；
  canvas 渲染只在浏览器执行，缺 `window`/`document` 时安全跳过。
- 遵守系统 `prefers-reduced-motion: reduce`——用户要求减少动态时直接不播。
- tsconfig strict；测试沿用 `node:test` + 红先行（RED-first）的 TDD 约定，
  回归用例编号从 R16 延续。

## 已定的实现取向（对话中已拍板）

- 动画技术：一个轻量 canvas 粒子引擎；三个动画 = 三组参数（颜色、重力、
  扩散形态、粒子形状），以后加新词/新动画只是加参数。
- 叠层：全屏 `position: fixed` canvas，`pointer-events: none`，播完即从 DOM 移除。
- 时长：以 mockup 为基准——烟花三次绽放后收尾（≤ 7s），撒花飘完为止（≤ 6s），
  下雪约 7s；粒子提前散尽则提前收。
- 冷却约 2 秒（mockup 实测过的手感）；单飞与冷却都是**全局**的（不分动画类型），
  避免「烟花刚播完下雪又铺满」。
- 匹配规则：对 stringify 后的完整文本做子串匹配；触发词必须是**词组**，
  不收单字（「雨」这类单字会误伤）。一次日志调用最多触发一个动画，
  多词命中取映射表中第一个匹配项。

## 留给实现者的（builder 自行决定，无需回问）

- 配置 API 形态（`configure({ effects: ... })` 或独立 setter 等），
  与现有 `configure`/`setXxx` 风格一致即可。
- 匹配的接入点（`prettyPrint` 内或各日志函数内）、子串匹配跑在转义前还是转义后。
- 粒子数量、颜色常量、物理参数的微调；canvas 用一层还是多层。
- 代码放 `src/index.ts` 内还是拆新模块（保证构建入口与类型产物不变即可）。
- 测试用例的具体划分与命名；`test/test.html` 的展示方式。

## 审阅后补充的裁定（已由 Claude 拍板，作者可推翻）

- **通道覆盖取上不取下**：不只是 debug/info/error/warning/success——`assert`
  失败信息、`time`/`timeEnd`/`timer`、`picture`、`countSummary`、被 `once`
  吞掉前的那次输出等，所有走日志输出的内容都参与触发词匹配。实现上宁可
  在输出总入口挂一个超集钩子，也不要逐个通道去补。
- **mockup 是视觉基准**：三个动画的粒子参数以浏览器里确认过的 mockup 为准，
  原件存档在 `2026-11-11-trigger-word-animations-mockup.html`（同目录）。
  参数微调可以，形态走样不行。
- **英文触发词大小写敏感**：按原文子串匹配（`OK` 不匹配 `ok`）。触发词以
  中文词组为主，影响极小；不做大小写折叠以免误伤。
- **`assert` 抛异常与动画无时序耦合**：动画是 `pointer-events: none` 层上的
  fire-and-forget，先抛后播、先播后抛都不影响正确性，无需特殊处理。

## 我的默认选择（如有异议请直接推翻）

1. **效果默认开启**——彩蛋是这个功能的全部意义，装了就该生效；
   提供一键整体关闭（并可替换词表）。
2. **日志被 logLevel 过滤掉时不播动画**——看不见的日志不该有彩蛋。
3. **匹配不区分全半角、不做分词**——触发词以中文词组为主，简单子串即可。
4. **所有走日志输出的通道都参与匹配**（debug/info/error/warning/success、
   table、group、rainbow、withPrefix 前缀后的输出）。
